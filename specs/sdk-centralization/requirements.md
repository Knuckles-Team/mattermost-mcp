# CONN-MATTERMOST-MCP-SDK-CENTRALIZATION requirements

Each row defines one requirement. [`status.json`](status.json) holds the generated state.

| ID | Requirement | Verification |
|---|---|---|
| `CONN-MATTERMOST-MCP-SDK-CENTRALIZATION-R001` | **Requests use the governed SDK client.** mattermost-mcp must send every vendor request through the SDK governed HTTP client with its resolved TLS profile and SDK auth. It must not build its own session. This row follows `SCION-CENTRALIZED-CAPABILITIES-R001`, `SCION-CENTRALIZED-CAPABILITIES-R003`, `SCION-CENTRALIZED-CAPABILITIES-R008`. Caller chain: an MCP tool of `mattermost_mcp/mcp_server.py` calls a domain client under `mattermost_mcp/api/`, which calls `ApiClientBase.request` (`mattermost_mcp/api/api_client_base.py:61`); the session was built by `create_http_client` in `ApiClientBase.__init__` (`mattermost_mcp/api/api_client_base.py:47`). Shape: `HttpClientOptions` with the resolved TLS profile and SDK auth in `mattermost_mcp/api/api_client_base.py`; reuses `scion_sdk.http.client.create_http_client` and builds no session of its own. Proving test: `tests/test_sdk_centralization.py::test_request_goes_through_the_governed_client`. | A unit test shows the API client holds an httpx client and a request carries the configured credential through a mock transport |
| `CONN-MATTERMOST-MCP-SDK-CENTRALIZATION-R002` | **SDK floor and dependency set.** The package must require the compatible public `scion-sdk[mcp]>=0.6.4,<0.7.0` distribution while retaining `scion_sdk` imports and must not pin requests or httpx while nothing imports them directly. Optional drivers come from SDK extras. This row follows `SCION-CENTRALIZED-CAPABILITIES-R040`, `SCION-CENTRALIZED-CAPABILITIES-R001`. Caller chain: the installer and the `dependency-readiness` pre-commit gate read `[project] dependencies` in `pyproject.toml`. Shape: the dependency `scion-sdk[mcp]>=0.6.4,<0.7.0` in `pyproject.toml` and no `requests` or `httpx` pin. Proving test: `tests/test_sdk_centralization.py::test_dependencies_have_no_unused_requests_pin`. | pyproject.toml shows the floor and no unused requests pin |
| `CONN-MATTERMOST-MCP-SDK-CENTRALIZATION-R003` | **Production wiring and hot path.** `ApiClientBase.__init__` in `mattermost_mcp/api/api_client_base.py` calls `create_http_client`, and every domain client reaches it through `request`. A transient 503 is retried by the SDK policy. This row follows `SCION-CENTRALIZED-CAPABILITIES-R001`, `SCION-CENTRALIZED-CAPABILITIES-R003`, `SCION-CENTRALIZED-CAPABILITIES-R008`. Caller chain: an MCP tool of `mattermost_mcp/mcp_server.py` calls a domain client, which calls `ApiClientBase.request` (`mattermost_mcp/api/api_client_base.py:61`); the governed session built at `mattermost_mcp/api/api_client_base.py:47` retries a transient status under the SDK policy. Shape: `create_http_client` in `mattermost_mcp/api/api_client_base.py` with the SDK retry policy; no connector-local retry loop. Proving test: `tests/test_sdk_centralization.py::test_transient_status_is_retried_by_the_sdk_client`. | A test builds the client with a mock transport, sees a 503 then a 200, and gets one result |
